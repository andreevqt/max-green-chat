# MAX · GREEN-API chat

Минимальный веб-клиент MAX на **Vite + React + TypeScript**. Реализует сценарий тестового задания: подключение по `idInstance` и `apiTokenInstance`, создание чата по телефону, отправка текста и получение ответа.

**[Открыть приложение](https://max-green-chat.vercel.app)** · [Исходники](https://github.com/andreevqt/max-green-chat) · [Проверки CI](https://github.com/andreevqt/max-green-chat/actions)

## Запуск

Требуется Node.js 24 LTS и npm.

```bash
npm ci
npm run dev
```

```bash
npm run test  # модульные и интеграционные тесты
npm run lint # ESLint
npm run build # TypeScript + production-сборка
```

## Подключение GREEN-API

1. Создайте **инстанс MAX** в [личном кабинете GREEN-API](https://console.green-api.com/) и авторизуйте его. Состояние должно быть `authorized`.
2. В настройках включите `incomingWebhook: yes`, очистите `webhookUrl`. Для обновления статусов доставки включите `outgoingWebhook: yes`. После изменений может потребоваться около минуты.
3. Введите `idInstance` и `apiTokenInstance` на странице приложения. API URL определяется по первым четырём цифрам ID; если адрес в кабинете отличается, введите его в поле «Другой адрес API».
4. Нажмите «Новый чат», введите телефон России (+7) или Беларуси (+375), при желании — имя.
5. Отправьте текст. Получатель отвечает в MAX; ответ автоматически появляется в чате.

Деморежим доступен без ключей и не выполняет сетевых запросов. Контакты и автоматические ответы в нём вымышлены.

## Интеграция

- `GetStateInstance` и `GetSettings` проверяют авторизацию и настройки при подключении.
- `CheckAccount` преобразует номер телефона в настоящий MAX `chatId`. Использовать телефон как `chatId` для двустороннего чата некорректно: входящие уведомления содержат другой идентификатор.
- `SendMessage` отправляет `{ chatId, message }`. Лимит: 4000 символов.
- `ReceiveNotification` используется последовательно с `receiveTimeout=5`. После обработки и сохранения сообщения вызывается `DeleteNotification`. Неподдерживаемые типы уведомлений пропускаются и подтверждаются, чтобы очередь не останавливалась.
- Дубликаты сообщений отсекаются по `idMessage`; статусы не откатываются при запоздалых уведомлениях. При ошибке получения используется задержка с увеличением до 30 секунд. При отключении запрос отменяется через `AbortController`.
- Ошибки отправки видны в чате; доступен ручной повтор. При сетевом таймауте результат отправки неизвестен, поэтому перед повтором следует проверить доставку в MAX.

Документация: [SendMessage](https://green-api.com/v3/docs/api/sending/SendMessage/), [HTTP API](https://green-api.com/v3/docs/api/receiving/technology-http-api/), [CheckAccount](https://green-api.com/v3/docs/api/service/CheckAccount/), [идентификаторы чатов](https://green-api.com/v3/docs/api/chat-id/).

## Архитектура и данные

`src/lib/api.ts` — типизированный HTTP-клиент; `src/lib/chat.ts` — чистые функции обработки сообщений; `src/hooks/useMessenger.ts` — состояние и цикл очереди; `src/components/` — формы, диалоги и чат.

Токен находится только в памяти вкладки, не сохраняется в Web Storage, Git или переменных окружения сборки. Запросы идут напрямую из браузера в GREEN-API по HTTPS; токен присутствует в URL запросов по контракту сервиса и виден владельцу вкладки в DevTools. Пользовательский API URL ограничен доменом GREEN-API.

История сохраняется в `sessionStorage`, отдельно по API URL и ID инстанса. После обновления требуется заново ввести ключи. Закрытие вкладки завершает её сессию. Это клиентский проект без серверной базы данных; для постоянного хранения и работы нескольких устройств потребуется backend. Один инстанс должен иметь один активный потребитель очереди: не открывайте параллельно несколько клиентов с теми же ключами.

## Deploy

Vercel автоматически распознаёт Vite: команда `npm run build`, каталог `dist`. `vercel.json` добавляет защитные HTTP-заголовки. Секреты на Vercel не требуются — каждый пользователь вводит собственные данные.

```bash
vercel --prod
```

При подключении GitHub-репозитория к проекту Vercel коммиты в `main` публикуются автоматически. GitHub Actions проверяет тесты, lint и сборку.

## Проверка

Тесты покрывают формат телефона, ограничения API URL, контракт отправки и подтверждения уведомлений, дедупликацию, статусы, деморежим, ошибку авторизации и полный сценарий с подменённым GREEN-API.

Для проверки реальной доставки нужен авторизованный инстанс GREEN-API и второй аккаунт MAX. Учётные данные не включены в репозиторий.

Независимый тестовый проект, не официальный клиент MAX.
